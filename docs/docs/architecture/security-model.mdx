# Security Model

## Non-Negotiables

1. Private key never leaves Secure Enclave
2. Nonce freshness enforced on Mac side (expiry + replay detection)
3. No proximity-only auth by default (biometric required for all surfaces)
4. Reason string always shown on iPhone
5. Pairing is explicit and one-time (QR code ceremony)
6. Timeout = fail open to password, not to grant
7. Daemon runs as user, not root

## Cryptographic Chain

<Accordion>
  <AccordionItem title="Pairing (one-time)">

- iPhone generates ECDSA P-256 key in Secure Enclave
- Public key transferred to Mac via BLE during QR pairing ceremony
- Mac stores public key in Keychain tagged with device UUID

  </AccordionItem>
  <AccordionItem title="Per-Session (ECDH)">

- Each BLE connection establishes ephemeral P-256 key pair on both sides
- Shared secret derived via ECDH → HKDF-SHA256 → AES-256 symmetric key
- All challenge/response data encrypted with AES-GCM

  </AccordionItem>
  <AccordionItem title="Per-Request (Challenge-Response)">

- Mac generates 32-byte nonce via `SecRandomCopyBytes`
- Nonce encrypted and sent to iPhone via BLE
- iPhone decrypts, prompts biometric, signs with Secure Enclave key
- Mac verifies ECDSA signature against pinned public key
- Nonce marked as seen (60s replay window)

  </AccordionItem>
</Accordion>

## Threat Model

### What we protect against

- **Credential theft**: passwords never entered for TouchBridge-approved auth
- **Replay attacks**: 32-byte nonces with 60s replay window + expiry
- **MITM on BLE**: ECDH session keys + AES-GCM encryption
- **Unauthorized pairing**: single-use token, QR ceremony required
- **Silent approval**: biometric gate on companion device

### What we don't protect against

- **Physical device theft**: if your phone is unlocked, an attacker could approve
- **Compromised Secure Enclave**: assumed impossible per Apple's threat model
- **macOS kernel compromise**: SIP-protected paths are out of scope
- **BLE jamming**: denial of service falls through to password

:::note
TouchBridge is fail-open to password. If anything goes wrong — daemon down, phone unreachable, BLE jammed, timeout — the normal password prompt appears. You are never locked out.
:::
